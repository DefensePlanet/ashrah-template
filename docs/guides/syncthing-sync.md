# Syncthing Sync — MacBook ↔ Mac Mini

**Status:** Live (configured 2026-03-01)
**Purpose:** Real-time bidirectional sync of `~/Catalyst` between MacBook Pro and Mac Mini over the local network and Tailscale.

---

## Architecture

```
MacBook Pro                          Mac Mini M4 Pro
~/Catalyst ◄────Syncthing────► ~/Catalyst
     │          (encrypted)          │
     └── git push (backup) ◄────────┘
         to GitHub from either
```

Both machines hold identical copies of the full Catalyst repo including `.git/`. Commit and push from either machine. GitHub is the backup, not the sync mechanism.

```
// macOS junk

// Docker volumes (machine-specific state)
**/docker-volumes

// GitNexus index (847MB, rebuilt per machine via gitnexus analyze)
.gitnexus

// Temp files
/tmp

// Logs (machine-specific, actively written)
logs/
registry/*.err
registry/*.out

// Monitoring data (machine-specific runtime state)
monitoring/prometheus/data/
monitoring/grafana-agent/positions.yaml

// Sync conflict files (auto-generated by Syncthing)
*.sync-conflict-*

// Syncthing own files
.stfolder
```

**Important:** `logs/` and `monitoring/` entries prevent sync conflicts from constantly-written log files. Without these, active processes on either machine generate sync conflict files that pile up.

## Auto-Start

Both machines run Syncthing as a Homebrew LaunchAgent:

```bash
# Installed on both machines
brew install syncthing    # v2.0.14
brew services start syncthing
```

**LaunchAgent plist:** `~/Library/LaunchAgents/homebrew.mxcl.syncthing.plist`

Starts automatically on login. Runs in the background. Web UI at http://localhost:8384.

**Tailscale** is also configured to auto-start on the Mac Mini (added to Login Items) so the Tailscale connection path is always available for remote sync.

## REST API Quick Reference

Both machines expose the Syncthing REST API on port 8384 (localhost only).

```bash
# Check sync status
curl -s -H "X-API-Key: {{SYNCTHING_API_KEY}}" \
  http://127.0.0.1:8384/rest/db/status?folder=catalyst

# Force rescan
curl -s -X POST -H "X-API-Key: {{SYNCTHING_API_KEY}}" \
  http://127.0.0.1:8384/rest/db/scan?folder=catalyst

# Restart Syncthing
curl -s -X POST -H "X-API-Key: {{SYNCTHING_API_KEY}}" \
  http://127.0.0.1:8384/rest/system/restart

# Check connection status
curl -s -H "X-API-Key: {{SYNCTHING_API_KEY}}" \
  http://127.0.0.1:8384/rest/system/connections

# Check what files are needed
curl -s -H "X-API-Key: {{SYNCTHING_API_KEY}}" \
  http://127.0.0.1:8384/rest/db/need?folder=catalyst
```

For Mac Mini remotely: `ssh {{USER_NAME}}@{{TAILSCALE_IP_MINI}} "curl -s -H 'X-API-Key: ...' http://127.0.0.1:8384/..."` or via Thunderbolt Bridge at `{{THUNDERBOLT_IP_MINI}}`.

## Safety Model

- Only one machine actively edits at a time ({{USER_NAME}}'s normal workflow)
- `.git/` is synced — both machines share branches, history, and remotes
- Conflict risk is minimal in single-user, single-active-machine setups
- If anything gets weird → `git clone` fresh from GitHub (the backup)
- `*.sync-conflict-*` files are auto-ignored by `.stignore`

## Troubleshooting

### Sync seems stuck
1. Check state: `curl -s -H "X-API-Key: ..." http://127.0.0.1:8384/rest/db/status?folder=catalyst`
2. If `state: scanning` — wait. Post-restart scans take ~15 min (rebuilds index of 50K+ files)
3. If `needFiles > 0` and not progressing — check for failing files with `rest/db/need`
4. Restart both: `curl -X POST ... /rest/system/restart`

### Sync conflict files appearing
Files being actively written on both machines simultaneously. Add the offending path to `.stignore`.

### Device ID collision after cloning
If a machine is set up from a clone, both will have the same device ID. Fix:
```bash
# On the cloned machine
rm ~/Library/Application\ Support/Syncthing/cert.pem
rm ~/Library/Application\ Support/Syncthing/key.pem
brew services restart syncthing
# New device ID is generated — re-add the device on the other machine
```

### .stignore changes not taking effect
After editing `.stignore`, force a rescan. If stale files persist in the index, restart Syncthing on both machines — the full rescan rebuilds the index with current ignore patterns (~15 min).
